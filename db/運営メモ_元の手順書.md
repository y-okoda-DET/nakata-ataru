# 文癖　デプロイ手順（Cloudflare）

ここでは、ゲームを Cloudflare に置き、「ランダム対戦（みんなのキャラ）」が動く状態にするまでを、順番に説明します。
所要時間は、はじめてでも30分〜1時間くらいです。

---

## 0. 全体像

公開するものは、次の3つです。

| もの | 役割 | このフォルダの中 |
|---|---|---|
| ゲームの画面 | 遊ぶ人のブラウザで動くページ | `public/index.html`、`public/freq-ja.js` |
| サーバーの処理（Pages Functions） | 登録・ランダム取得・通報・取り消しを受け付ける | `functions/api/buntai/[[path]].js` |
| データベース（D1） | 登録されたキャラを保存する | `schema.sql`（テーブルの作り方） |

`wrangler.toml` は、この3つをどうつなぐかを書いた設定ファイルです。

> **大事な注意**：Cloudflare のダッシュボードに「ドラッグ＆ドロップでアップロード」する方法では、サーバーの処理（`functions` フォルダ）が動きません。この手順書のとおり、`wrangler` というコマンドでデプロイしてください（GitHub 連携を使う方法は 9章）。

---

## 1. 準備

### 1-1. Node.js を入れる
`wrangler` を動かすのに Node.js が必要です。

1. https://nodejs.org/ を開き、**LTS（推奨版）** をダウンロードしてインストールします。
2. ターミナル（Mac は「ターミナル」、Windows は「PowerShell」）を開き、次を入力して Enter を押します。

```
node -v
```

`v20.〇〇` のように数字が出ればOKです（v18 以上なら動きます）。

### 1-2. このフォルダをパソコンに置く
受け取った `buntai-beast-site.zip` を解凍し、好きな場所に置きます。
ここでは例として、デスクトップに `buntai-beast-site` フォルダを置いたとします。

### 1-3. ターミナルでフォルダに移動する

Mac：
```
cd ~/Desktop/buntai-beast-site
```

Windows：
```
cd $HOME\Desktop\buntai-beast-site
```

> ここから先のコマンドは、**すべてこのフォルダの中で**実行します。ターミナルを閉じたら、もう一度 `cd` からやり直してください。

---

## 2. Cloudflare にログインする

```
npx wrangler login
```

- はじめての場合、「wrangler をインストールしますか？（Ok to proceed?）」と聞かれたら `y` を押します。
- ブラウザが開き、Cloudflare のログイン画面が出ます。ログインして **「Allow（許可）」** を押します。
- ターミナルに `Successfully logged in` と出れば完了です。

---

## 3. データベース（D1）を作る

### 3-1. データベースを作成

```
npx wrangler d1 create buntai-beast
```

次のような表示が出ます。

```
[[d1_databases]]
binding = "DB"
database_name = "buntai-beast"
database_id = "1a2b3c4d-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

### 3-2. ID を設定ファイルに貼る

`wrangler.toml` をテキストエディタ（メモ帳や VS Code など）で開き、

```
database_id = "ここに作成したD1のIDを貼る"
```

の `ここに作成したD1のIDを貼る` を、さっき表示された `database_id` の値（`1a2b3c4d-...`）に書き換えて保存します。
`"`（ダブルクォーテーション）は消さないでください。

### 3-3. テーブルを作る

```
npx wrangler d1 execute buntai-beast --remote --file=./schema.sql
```

「本当に実行しますか？」と聞かれたら `y` を押します。
最後に `"success": true` のような表示が出れば完了です。

> `--remote` を付け忘れると、パソコンの中の練習用データベースにだけ作られてしまいます。必ず付けてください。

> あとで `schema.sql` が新しくなったとき（テーブルが増えたとき）も、このコマンドをもう一度実行すれば足りない分だけ作られます。今あるデータは消えません。

---

## 4. Pages のプロジェクトを作る

```
npx wrangler pages project create buntai-beast --production-branch=main
```

- 完了すると `https://buntai-beast.pages.dev` のようなアドレスが表示されます。
- 「その名前はもう使われています」と出た場合は、`buntai-beast` の部分を別の名前（例：`buntai-beast-yourname`）に変えて実行してください。その場合、**`wrangler.toml` の1行目の `name = "buntai-beast"` も同じ名前に変えて**、このあとのコマンドの `--project-name=` も同じ名前にしてください。

---

## 5. 秘密の文字列（IP_SALT）を設定する

登録数の制限のために、遊ぶ人の IP アドレスを「そのまま保存せず」、秘密の文字列と混ぜて読めない形（ハッシュ）にして保存しています。その秘密の文字列を設定します。

### 5-1. ランダムな文字列を作る

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

64文字くらいの英数字が表示されます。これをコピーします。

### 5-2. Cloudflare に保存する

```
npx wrangler pages secret put IP_SALT --project-name=buntai-beast
```

`Enter a secret value:` と聞かれたら、さっきコピーした文字列を貼り付けて Enter を押します（画面には表示されません）。

> この文字列は誰にも教えないでください。メモしておく必要はありません。

---

## 6. デプロイする

```
npx wrangler pages deploy
```

- 「どのブランチにしますか」などと聞かれたら、そのまま Enter で構いません。
- 最後に `✨ Deployment complete!` と、アドレスが表示されれば完了です。

---

## 7. 動作を確かめる

1. ブラウザで `https://buntai-beast.pages.dev/api/buntai/health` を開きます。
   **`{"ok":true}` と表示されればサーバーとデータベースはつながっています。**
   - `データベースがつながっていません` と出る → 3-2 の ID の貼り付けを確認し、もう一度 6 を実行。
   - `404` やゲームの画面が出る → `functions` フォルダが一緒にデプロイされていません。フォルダの中で 6 を実行しているか確認。
2. `https://buntai-beast.pages.dev/` を開き、例文などでキャラを作ります。
3. 「対戦」タブに **「ランダム対戦」** と **「みんなの対戦相手として登録する」** が出ていれば成功です。
4. 同意にチェックを入れて登録 → 別のブラウザ（スマホなど）で別の文章からキャラを作る → 「ランダム対戦」に最初のキャラが出てくることを確認します。
5. キャラ画面の「Xで見せる」を押し、投稿文の最後のリンクが `?b=` で始まる短い形になっていれば、短いリンクも動いています。
6. リンクのプレビュー（Xなどに貼ったときの画像とタイトル）は、X の投稿画面にリンクを貼ってみると確認できます。画像が出ないときは、数分おいてからもう一度試してください（Xは一度読んだプレビューをしばらく覚えています）。

## 8. 自分のドメインで公開する

### パターンA：サブドメインで公開する（いちばん簡単）
例：`game.example.com` で公開する場合

1. Cloudflare ダッシュボード → **Workers & Pages** → `buntai-beast` を開く
2. **カスタムドメイン（Custom domains）** → **カスタムドメインを設定**
3. `game.example.com` を入力して進める（そのドメインが同じ Cloudflare アカウントにあれば、設定は自動で入ります）

数分〜数十分で `https://game.example.com/` から遊べるようになります。

### パターンB：今あるサイトの中に入れる（例：`example.com/buntai/`）
今のサイトがすでに **Cloudflare Pages** で動いている場合は、そのプロジェクトに組み込めます。

1. 今のサイトの公開フォルダの中に `buntai` フォルダを作り、`public/index.html`・`public/freq-ja.js`・`public/og.png` を入れる
   → `https://example.com/buntai/` で開けるようになります
2. 今のサイトのプロジェクトのいちばん上に、`functions/api/buntai/[[path]].js` と `functions/_middleware.js` を同じ場所関係でコピーする
   （すでに `functions` フォルダがある場合は、その中に足す。すでに `_middleware.js` がある場合は相談してください）
3. 今のサイトの公開フォルダのいちばん上に `_routes.json` を置き、中身を次のようにする（サーバーの処理を文癖のページとAPIだけで動かすための設定です。ほかのページは今までどおり速く・無料枠を使わずに表示されます）
   ```json
   { "version": 1, "include": ["/buntai/", "/buntai/index.html", "/api/buntai/*"], "exclude": [] }
   ```
   （すでに `_routes.json` がある場合は、`include` にこの3つを足す）
4. 今のサイトの設定に、D1 のつなぎ込み（`binding = "DB"`）と `IP_SALT` を追加する
   - `wrangler.toml` を使っている場合：3-2 と同じ `[[d1_databases]]` の4行を追加
   - ダッシュボードで設定している場合：プロジェクト → **設定（Settings）** → **バインディング（Bindings）** → **D1 データベース** を追加（変数名は `DB`）、**変数とシークレット** に `IP_SALT` を追加
5. いつもの方法でデプロイ

> 今のサイトが Pages ではなく Workers や別のサービスで動いている場合は、組み込み方が変わります。そのときは構成を教えてください。

## 9. （参考）GitHub 連携で公開する場合

GitHub のリポジトリと Cloudflare Pages をつないで、プッシュするたびに自動で公開する方法もあります。

1. このフォルダの中身を GitHub のリポジトリに入れる（`node_modules` や `.wrangler` は入れない）
2. ダッシュボード → Workers & Pages → 作成 → Pages → **Git に接続**
3. ビルドの設定：フレームワークは「なし」、ビルドコマンドは空欄、**ビルド出力ディレクトリは `public`**
4. 作成後、プロジェクトの **設定 → バインディング** で D1（変数名 `DB`）を、**変数とシークレット** で `IP_SALT` を追加して、もう一度デプロイ

3（テーブル作成）と 5-1（文字列づくり）は、この方法でも同じように必要です。

## 10. 運営のしかた

ダッシュボード → **Workers & Pages** の左メニュー → **D1** → `buntai-beast` → **コンソール** で、SQL を実行して管理できます。

### 通報の多いキャラを見る
```sql
SELECT id, name, reports, hidden, datetime(created_at/1000, 'unixepoch', '+9 hours') AS 登録日時
FROM beasts ORDER BY reports DESC, created_at DESC LIMIT 30;
```

### そのキャラの中身を確かめる
```sql
SELECT code FROM beasts WHERE id = 'ここにID';
```
出てきた `BB4-...` を、`https://（あなたのサイト）/?vs=BB4-...` の形で開くと、ゲーム上でそのキャラを「挑戦状」として見られます。

### 非表示にする／もとに戻す／消す
```sql
UPDATE beasts SET hidden = 1 WHERE id = 'ここにID';                -- 非表示
UPDATE beasts SET hidden = 0, reports = 0 WHERE id = 'ここにID';   -- もとに戻す（誤通報だったとき）
DELETE FROM beasts WHERE id = 'ここにID';                          -- 完全に消す
```

### 短い対戦リンクを消す
対戦リンク（`?b=ID`）は、ランダム対戦には出ませんが、リンクを知っている人は開けます。問題のあるリンクを止めたいときは：
```sql
SELECT id, name, datetime(created_at/1000, 'unixepoch', '+9 hours') AS 作成日時 FROM links ORDER BY created_at DESC LIMIT 30;
DELETE FROM links WHERE id = 'ここにID';
```

### 登録数を見る
```sql
SELECT COUNT(*) AS 全体, SUM(hidden) AS 非表示 FROM beasts;
```

### 昨日のボスと勝ち数ランキングを見る
「昨日のボス」は、日本時間の昨日にいちばん多く勝った登録キャラです（勝ち数が同じなら対戦数が少ないほう）。日付のところを見たい日に変えて実行します。
```sql
SELECT b.name, SUM(t.won) AS 勝ち, COUNT(*) AS 対戦
FROM battles t JOIN beasts b ON b.id = t.beast_id
WHERE t.day = '2026-10-09' AND b.hidden = 0
GROUP BY t.beast_id ORDER BY 勝ち DESC, 対戦 ASC LIMIT 10;
```
ボスにふさわしくないキャラは、上の「非表示にする」で隠せば、次に勝ち数の多いキャラがボスになります。

### 登録キャラの通算成績を見る
マイキャラの「挑まれた対戦」に出る数字です（ほかの人のランダム対戦・ボス戦での勝ち負け。1日ごとの記録を片づけても残ります）。
```sql
SELECT name, wins AS 勝ち, losses AS 負け FROM beasts WHERE hidden = 0 ORDER BY wins DESC LIMIT 20;
```

> **すでにテーブルを作ってしまった場合**：この版で `beasts` に `wins`・`losses` の列が増えました。以前の `schema.sql` で作った人は、一度だけ次を実行してください（新しく作る人は不要です）。
> ```
> npx wrangler d1 execute buntai-beast --remote --command "ALTER TABLE beasts ADD COLUMN wins INTEGER NOT NULL DEFAULT 0; ALTER TABLE beasts ADD COLUMN losses INTEGER NOT NULL DEFAULT 0;"
> ```

### ボス級の出かたを確かめる
登録されたキャラのうち、ボス級の割合です（ねらいは5%くらい）。公開してしばらくしたら確認して、多すぎ・少なすぎるときは相談してください。
```sql
SELECT COUNT(*) AS 全体, SUM(bk) AS ボス級, ROUND(100.0 * SUM(bk) / COUNT(*), 1) AS 割合 FROM beasts;
```

### 自動で決まっているルール（`functions/api/buntai/[[path]].js` の先頭で変えられます）

| 項目 | 今の設定 |
|---|---|
| 1人（1回線）が1日に登録できる数 | 5体 |
| 1人が1日に通報できる数 | 20件 |
| 自動で非表示になる通報数 | 別々の3人から |
| 対戦結果を数える回数 | 同じ人と同じキャラの組み合わせは1日1回だけ |
| 登録した本人の回線からの対戦 | 数えない（自分で自分を勝たせられないように） |
| 対戦券の有効時間 | 1時間（相手を表示してから1時間以内の対戦だけ数える） |
| 1人が1日に記録できる対戦の数 | 300件 |
| 対戦記録を残す日数 | 30日（古いものは自動で片づけ） |
| 1人が1日に作れる短い対戦リンク | 50本（同じキャラは同じリンクになるので数えない） |

- **NGワードを足す**：同じファイルの `NG_WORDS` に、ひらがなか漢字で足して、6 のデプロイをやり直します。カタカナ・全角半角の違いは自動でそろえて照合します。2文字以下のような短い言葉は、ふつうの言葉の一部に誤って当たりやすいので避けてください。
- **注意**：学校や会社など、同じ回線を大勢で使っている場所では、1日の登録数の制限をみんなで共有することになります。

## 11. 更新するとき

ゲームやサーバーの処理を直したら、ファイルを差し替えて、フォルダの中で

```
npx wrangler pages deploy
```

を実行するだけです。登録されたキャラ（データベース）は消えません。

---

## 12. 費用について

Pages・Pages Functions・D1 には無料枠があり、個人サイトの規模なら無料枠に収まる見込みです。
ただし無料枠の上限は変わることがあるので、ダッシュボードの **使用状況（Usage）** をときどき確認してください。心配な場合は、Cloudflare の料金ページで最新の上限を確認できます。

## 13. プライバシーについての表記（例）

サイトのどこか（ゲームの下や、プライバシーポリシーのページ）に、次のような内容を書いておくと安心です。

> 文癖では、貼り付けた文章はお使いの端末の中だけで読み取り、サーバーには送信しません。
> 「みんなの対戦相手として登録する」を選んだ場合に限り、キャラの設定（名前・正体・決めゼリフ・技・ステータス・見た目）をサーバーに保存し、ほかの利用者の対戦相手として表示します。「技で飛ばす一文も公開する」を選んだ場合は、文章の一部（技の一文）も保存されます。
> 登録数の制限と対戦結果の集計のため、IPアドレスを元に戻せない形（ハッシュ）に変換して保存します。
> ランダム対戦の勝ち負けを記録し、前日にいちばん勝ったキャラを「昨日のボス」として表示します。
> 「対戦リンクを送る」「Xで見せる／共有する」を使うと、リンクを短くするために、キャラの設定をサーバーに保存します（ランダム対戦には出ません）。
> 登録はゲーム画面からいつでも取り消せます。不適切な内容は通報でき、一定数の通報で自動的に非表示になります。
> 作ったキャラと、ランダム対戦の戦績（マイキャラ）は、お使いのブラウザの中にだけ保存されます。
> 「AIでもっと深く読む」を使った場合、文章は利用者が選んだAIサービスに送られます。

## 14. 困ったとき

| 症状 | よくある原因と対処 |
|---|---|
| `npx: command not found` | Node.js が入っていません。1-1 をやり直してください |
| `/api/buntai/health` が 404 | `functions` フォルダがデプロイされていません。ドラッグ＆ドロップではなく 6 のコマンドで、フォルダの中から実行してください |
| `データベースがつながっていません` | `wrangler.toml` の `database_id` が違う、または `binding = "DB"` の名前が違います |
| `no such table: beasts` | 3-3 を `--remote` 付きで実行していません |
| 「対戦」タブにランダム対戦が出ない | `https://` で開いているか、`/api/buntai/health` が `{"ok":true}` か確認してください。ファイルを直接開いた場合（`file://`）は出ません |
| 登録しようとすると「1日5体まで」 | 同じ回線で今日すでに5体登録しています。明日になれば登録できます |
